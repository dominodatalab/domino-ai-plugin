# Dataset best practices

What belongs in a Dataset, how to lay it out, which formats to use, snapshotting before changes,
and reading data larger than memory.

Docs: https://docs.domino.ai/cloud/platform-capabilities/core-concepts/data/datasets/manage-large-data
and https://docs.domino.ai/cloud/platform-capabilities/core-concepts/data/datasets/local-data.

## What goes where

| Data | Storage | Why |
|---|---|---|
| Large or static data (training sets, images, extracts) | Domino Dataset | No file-count or size cap from Domino; mounted, versioned, shareable |
| Code, notebooks, small configs | Project files (Git repository or DFS) | Versioned with the code; Project files have a default 10,000-file sync limit |
| Outputs of a Job you want recorded with the run | Project files or `/mnt/artifacts` in Git-based Projects | Synced back as results (https://docs.domino.ai/cloud/platform-capabilities/core-concepts/projects/files-artifacts-and-results) |
| Scratch | `/tmp` | Discarded with the execution |
| Data over a few TB, or already in object storage | Data Source connector | Query or stream it instead of copying (domino-data-sdk skill) |
| Multi-terabyte data needing instant snapshots | NetApp Volume | netapp-volumes skill |

Many small, frequently changing files (logs) sync slowly as Project files; keep them compressed
or move them to a Dataset. Local CLI users should keep large data out of Project files so
`domino download` and `domino sync` stay fast.

## Layout

```
<dataset-root>/my-dataset/
  raw/            customers.csv, transactions.csv      (as received, never edited)
  processed/      features.parquet, labels.parquet     (derived, regenerated by code)
  metadata/       schema.json, README.md               (provenance, column meanings)
```

`<dataset-root>` is `/mnt/data` (Git-based) or `/domino/datasets/local` (DFS); see
[MOUNT-PATHS.md](./MOUNT-PATHS.md).

## Formats

```python
df.to_parquet(f"{root}/my-dataset/processed/features.parquet")   # columnar, compressed, typed
df.to_feather(f"{root}/my-dataset/processed/frame.feather")      # fast pandas round-trip

import h5py
with h5py.File(f"{root}/my-dataset/processed/tensors.h5", "w") as f:
    f.create_dataset("features", data=features)                   # large numerical arrays
```

Parquet over CSV for anything you read more than once; partition large tables by a column you
filter on; prefer files of 100 MB to 1 GB over thousands of tiny files.

## Record provenance

```python
import json
from datetime import date

metadata = {
    "created": date.today().isoformat(),
    "source": "customer warehouse, sales schema",
    "columns": {"id": "int", "name": "string", "value": "float"},
}
with open(f"{root}/my-dataset/metadata/schema.json", "w") as f:
    json.dump(metadata, f, indent=2)
```

## Snapshot before you change data

Take a snapshot before a transformation so the previous state stays readable at
`snapshots/<name>/<n>` and can be tagged or copied into a new Dataset. From a Workspace or Job,
call the API through the proxy (outside a run use a Personal Access Token instead; see
[API.md](./API.md)):

```bash
curl -sS -X POST "$DOMINO_API_PROXY/api/datasetrw/v1/datasets/$DATASET_ID/snapshots" \
  -H "Content-Type: application/json" \
  -d '{"relativeFilePaths": ["*"]}'
```

Or `domino create-snapshot <owner>/<project>/<dataset>` from a machine with the CLI
([domino-cli](../domino-cli/SKILL.md)). Wait for
the snapshot's `status` to become `active` before editing files. Tag the ones you will refer to
(`baseline`, `pre-cleanup`) and pin Jobs to a snapshot when a run must be reproducible.

A snapshot is not mounted in the execution that took it; executions started after it became
`active` mount it, and [API.md](./API.md) shows how to read it immediately through the internal
file route or `DatasetClient`.

Large uploads from a laptop: `domino upload-dataset` reads `DOMINO_UPLOAD_CHUNK_BYTES` (default
3 MB) and `DOMINO_UPLOAD_THREADS` (default 8) to tune chunking and parallelism.

## Reading data larger than memory

Chunked:

```python
for chunk in pd.read_csv(f"{root}/my-dataset/raw/large_file.csv", chunksize=100_000):
    process(chunk)
```

Lazy with Dask:

```python
import dask.dataframe as dd

ddf = dd.read_parquet(f"{root}/my-dataset/processed/large_data.parquet")
result = ddf.groupby("category").mean().compute()
```

Column projection and predicate pushdown with PyArrow:

```python
import pyarrow.parquet as pq

table = pq.read_table(f"{root}/my-dataset/processed/features.parquet",
                      columns=["id", "value"], filters=[("region", "=", "US")])
```

Memory-mapped arrays:

```python
import numpy as np

data = np.memmap(f"{root}/my-dataset/processed/features.dat", dtype="float32", mode="r",
                 shape=(1_000_000, 100))
```

## Snapshot limits and housekeeping

Domino 6.3 enforces `com.cerebro.domino.dataset.quota.maxActiveSnapshotsPerDataset` (default
20) and `com.cerebro.domino.dataset.quota.maxDatasetsPerProject` while
`com.cerebro.domino.dataset.quota.enabled` is `true`
(https://docs.domino.ai/6.3/admin/configuration/central-configuration#read-write-datasets); on
Domino Cloud, Domino Support sets the limits. At the limit an execution that would write a
snapshot errors, and a manual **Take Snapshot** marks the oldest snapshot for deletion if you
proceed; a marked snapshot stops mounting, and nothing is permanently deleted until an admin
acts (https://docs.domino.ai/cloud/admin/data-administration/datasets#set-limits-on-dataset-usage).

Housekeeping: delete snapshots you no longer need (an Owner marks, an admin purges from
**Admin > Manage resources > Datasets**; on 6.3 the recovery window is
`com.cerebro.domino.dataset.graceTimeForDeletion`, default 15 minutes); exempt a Project only
when policy allows (**Settings > Hardware & Environment > Ignore Dataset Limits**); refresh
Datasets from external Data Sources with a scheduled Job rather than manual uploads. Routes for
deleting, marking, restoring, reading the cap and setting the exemption:
[API.md](./API.md#snapshot-deletion-and-limits-non-public-routes).
